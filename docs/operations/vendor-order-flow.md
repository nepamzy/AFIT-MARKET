# Shop order flow, automatic refunds and QR hand-over

- **Payment is confirmed by Paystack** (webhook). The shop never confirms payment. Orders show "✓ Payment confirmed".
- **Shop buttons:** a paid order has only **Accept order** (preparing starts at once) and **Decline order** (a reason is required and is shown to the customer). A preparing order has **Mark ready**. The old "Start preparing" step is gone (the database still accepts it as a no-op).
- **Decline = automatic refund.** `vendor_transition_order('reject')` cancels the order and releases stock. The server then calls `startAutoRefund` (`src/server/modules/refunds/auto.ts`): the database makes one full refund (`source = 'auto'`, approved by the system, `processing`), the server asks Paystack `POST /refund` for the payment reference, and records the outcome (`refund_provider_outcome`). A Paystack "pending" answer is finished by the `refund.processed` / `refund.failed` webhook. The daily job `settle-refunds` starts any refund that never started and re-checks waiting ones. A refund Paystack refuses raises a `auto_refund_failed` reconciliation flag for finance. How fast the bank shows the money is up to the bank.
- **Not yet tested against the real Paystack test servers** (only against the local fake). Check the first real decline in test mode.
- **QR hand-over (rider to shop):** the rider's code screen also shows a QR (`afit-pickup:<code>`). The shop's Handover page has **Scan rider's QR code** (camera, only after the tap); a scan confirms the hand-over at once. Typing the code still works. `Permissions-Policy` now allows the camera for this site only (`camera=(self)`).

## Automatic ready, unanswered orders, and a shop's own riders

- **Automatic ready** (optional, chosen when the shop applies and editable in Shop settings): after the shop accepts, an order becomes ready by itself once the chosen time (30 min, 1 h, 1.5 h, 2 h, 3 h) has passed **since the customer paid**. `public.auto_ready_run()` does it; the database scheduler (`pg_cron`, every minute, job `afit-auto-ready`) calls it, and the daily job calls it too as a fallback. On the live project pg_cron is enabled (it also runs `afit-dispatch-notifications` every minute, so the customer's e-mail and phone pop-up for the automatic step go out within about a minute). If pg_cron were ever disabled, ready would fall back to the daily job and could be up to a day late.
- **Unanswered paid orders**: after `vendor_response_hours` (default 15, allowed 15 to 20, set by the administrator) with no accept or decline, `auto_decline_unanswered()` declines the order ("The shop did not answer in time") and the automatic refund starts. This runs in the daily job, so an order is declined between 15 hours and about 39 hours after payment (the 24-hour limit is only a design reason for choosing 15 to 20 hours, not a promise).
- **A shop's own riders** (Vendor > My riders): the owner adds a name and gets a permanent 5-digit code. The rider types it in the optional "Shop code" boxes when signing up as a rider, or on the Rider home page later. The rider still sends the normal documents and an administrator still approves them. A linked rider sees and accepts only that shop's orders; riders without a link see every shop. The owner can remove a rider at any time.
